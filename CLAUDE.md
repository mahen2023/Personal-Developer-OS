# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A self-hosted, single-user developer command centre: projects, notes, tasks,
infrastructure inventory, troubleshooting knowledge and an encrypted vault, all
connected through a project-centric graph. npm workspaces monorepo —
`apps/api` (NestJS) and `apps/web` (Next.js).

Built in phases against a fixed specification. **All eight phases are complete.**
The reasoning behind the structure is in `docs/ARCHITECTURE.md`.

Three subsystems arrived late and are easy to miss:

- **Retrieval** (`src/ai/`) — everything you write is chunked, embedded and
  stored in a pgvector column. Three providers: a lexical one that runs offline
  with no account, OpenAI's, and Ollama's, all emitting 384 dimensions so the
  column fits any of them. Answers are generated by Claude only when
  `AI_ENABLED=true`; without it retrieval still works and returns the passages
  themselves.
- **The Developer Intelligence console** (`src/ai/chat/`, `providers/`,
  `conversations/`, `models/`, `settings/`) — a streaming assistant that runs
  entirely on a local Ollama. It sits on top of the retrieval above rather than
  beside it: the same `chunks` rows are the sources it cites. Everything that
  speaks Ollama's HTTP API lives in `providers/ollama.provider.ts` and nowhere
  else.
- **Jobs** (`src/jobs/`) — BullMQ over Redis. Nightly expiry, task, rotation
  and index scans, plus backups and integration sync. Only the worker process
  consumes (see below).
- **Integrations** (`src/integrations/`) — GitHub, GitLab and Cloudflare, all
  plain REST over `fetch`, all optional.

## Commands

```bash
npm install
npm run infra:up                 # postgres + redis via docker compose
npm run db:migrate               # create + apply a migration
npm run dev                      # api :4000 and web :3000, both watching

npm run build                    # both workspaces
npm run lint                     # both workspaces
npm test                         # API unit tests (jest)
npm run test:e2e                 # playwright, needs a running stack
npm run worker                   # background jobs; nothing runs on a schedule without it

npm run auth:reset-password -- you@example.com   # no email flow exists, by design
```

The console needs Ollama, which is not part of the compose stack — it wants the
host's GPU:

```bash
ollama serve                     # or the desktop app
ollama pull llama3.1:8b          # any chat model; the console discovers it
ollama pull nomic-embed-text     # only for EMBEDDING_PROVIDER=ollama
```

Single tests:

```bash
npm test -w @devos/api -- security.spec       # one file
npm test -w @devos/api -- -t "redact"         # one test by name
npx playwright test -g "command palette"      # one e2e test
npx playwright test --ui                      # debug e2e interactively
```

Database:

```bash
npm run db:studio                # Prisma Studio
npm run db:push                  # prototype a schema change without a migration
npm run db:seed                  # demo data (needs an account to exist first)
npm run db:seed -- --clear       # remove only the demo rows
```

## Environment

There is **one `.env`, at the repo root**, shared by the API, the worker and
docker compose. Two things depend on that:

- The Prisma CLI cannot see it from `apps/api`, so every `db:*` script is
  wrapped in `dotenv -e ../../.env --`. Keep that prefix on any new one.
- `ConfigModule` loads `../../.env`, and skips the file entirely when
  `NODE_ENV=production` (compose passes real environment variables instead).

`apps/api/src/config/configuration.ts` is the only place `process.env` is read.
Add new settings there, not inline — `validateEnv()` runs at boot and fails
loudly on a placeholder value.

## Architecture rules

These are load-bearing. Breaking them produces code that compiles and is wrong.

**Everything hangs off a project.** Nearly every table has an optional
`projectId`. New entities should too — it is what makes the project workspace,
the context panel and scoped search work without bespoke joins.

**Scope every query by `userId`.** There is no organisation or permission model;
row ownership is the entire authorisation story. A query without it is a data
leak waiting for a second account.

**`JwtAuthGuard` is global** (`APP_GUARD` in `app.module.ts`). New controllers
are protected by default; opt out with `@Public()`. `ThrottlerGuard` runs first,
so unauthenticated floods never reach Argon2.

**`lib/navigation.ts` is the single source of truth for the frontend IA.** It
drives the rail, the `g`-chord shortcuts, the palette's "go to" entries, the
breadcrumb and the status bar. A new module means one row there. Never hardcode a
route in two places.

**Polymorphic relations are enforced in the service layer, not the database.**
`entity_tags`, `entity_links`, `activities`, `notifications` and `documents` key
on `EntityType` + `entityId`. Prisma cannot validate those; the service must.

**Only the worker consumes the queue.** `JobsProcessor` is declared with
`autorun: false`, and only the worker calls `worker.run()` — gated on
`WORKER=true`, which `worker.ts` sets for itself. The API creates the same queue
objects so it can enqueue and inspect, but must never process. Pausing after
boot is not equivalent: it was tried, and the API had already claimed a job.

**Notifications are live claims, not a log.** A scan re-raises every warning it
still believes; `dedupeKey` stops that becoming duplicates, and `reconcile()`
deletes every notification of a kind that the latest scan did not re-assert.
That is what makes an empty list mean something. The log is the activity feed.

**The index is derived data.** `chunks` rows can always be rebuilt from the
records they came from, which is why writes call `indexer.touch()` without
awaiting it and why nothing backs them up. If you add a record type worth
quoting back, add it to `SOURCES` in `ai/indexer.service.ts` and hook the write
path — or set `indexAs` in its `CrudConfig` if it uses `CrudService`.

**Count days with `common/dates.ts`, never by subtracting timestamps.**
`daysUntil()` compares midnights. Elapsed-millisecond arithmetic gives 2.x days
for something three days away, so `floor` and `ceil` disagree — the dashboard,
the detail page and the nightly scan each had a different answer for the same
certificate before this was shared.

**An error id means "we broke it", so 4xx responses do not carry one.**
`AllExceptionsFilter` returns `errorId` on 5xx only. Printing a reference under
"your password needs at least 12 characters" makes a typo look like a system
fault. The id is still logged for every status, so a warn line stays traceable.
Validation messages are built by `common/validation.ts`, which names the field
in every one — a form with three inputs must never answer "use at least 12
characters" and leave the user guessing which.

**The console's context is assembled in one place.** `chat/context.service.ts`
decides everything a model is shown. Prose types (note, solution, issue, ADR,
meeting, snippet, document) are retrieved from the index by meaning; row types
(task, server, database, domain, deployment, environment, repository) are never
indexed and are listed as a compact brief instead — a paraphrase of a hostname
is worse than the hostname. Adding a record type to the console means adding it
there, not in a prompt string. Prompts themselves are built by pure functions in
`chat/prompt.ts`, which is what makes them testable.

**Never break the secret boundary.** Credentials belong in `vault_items` as
ciphertext. Infrastructure rows hold a _reference_ (`servers.sshKeyId`,
`databases.credentialId`, `env_variables.vaultItemId`) — never a value. When
adding a field whose name suggests a secret, add it to the `SENSITIVE_KEYS`
pattern in `common/filters/all-exceptions.filter.ts`, which `redact()` applies to
logs, error bodies and the activity feed. See `docs/SECURITY.md`.

Three things keep secrets away from the local model, and all three should stay:
vault items are not indexed, so retrieval cannot surface one; `VAULT_ITEM` is
absent from `SELECTABLE_SOURCES`; and `assertNoSecrets()` drops the type even if
a stored conversation asks for it. The infrastructure brief selects columns
explicitly for the same reason — a future column called `password` cannot arrive
in a prompt by being added to the schema.

Two deliberate exceptions, both documented where they live. Vault items are
never indexed, so no secret can reach an AI prompt. Integration tokens _are_
decryptable by the server — the nightly sync runs with nobody signed in — which
is why they are opt-in, one per provider, and shown with their scopes.

## Adding a module

Backend, in `apps/api/src/<module>/`:

1. `<module>.service.ts` — Prisma queries, all scoped by `userId`.
2. `<module>.controller.ts` — REST: `GET /`, `POST /`, `GET /:id`, `PATCH /:id`,
   `DELETE /:id`. Follow the shape exactly; consistency is the API design.
3. `<module>.dto.ts` — extend `PaginationDto` for the list filters rather than
   redeclaring `page`/`limit`/`sort`.
4. `<module>.module.ts`, registered in `app.module.ts`.
5. Call `ActivityService.record()` on writes.

Frontend:

1. Add the row to `lib/navigation.ts` (this creates the shortcut and the palette
   entry for free).
2. Replace the `ModulePlaceholder` page under `app/(workspace)/<module>/`.
3. Call `useContextPanel()` on detail pages so the right panel shows what the
   record connects to.

## Design system

The visual identity is the product's main differentiator, and it is enforced by
tokens in `apps/web/src/app/globals.css`. When writing UI:

- Use semantic tokens (`var(--surface-raised)`, `var(--accent)`,
  `var(--danger)`), never a hex.
- Separate surfaces with 1px hairlines, not shadows. Radii stay ≤ 6px — nothing
  should read as a floating card.
- Colour means a signal. The brass accent is for interaction; everything else is
  near-monochrome.
- `.mono` is only for machine-readable values (IPs, commands, keys, SHAs).
  `.label` is the small tracked uppercase used for section headings.
- Animate with the existing classes (`anim-enter`, `anim-palette`, `stagger`,
  `skeleton`) and the `--fast`/`--base`/`--slow` durations. The
  `prefers-reduced-motion` block already covers anything using them.
- Empty states say what the screen is _for_ and offer the next action. Never
  "No data found". Loading states are skeletons or contextual text, not spinners.
- Both themes are complete palettes. If you add a token, add it to both.

## Testing

Two habits the suite depends on, both learned the hard way:

- **Find controls by accessible name, never by position.** `header button` last
  is also the sign-out button whenever a detail header has not rendered yet;
  clicking it revokes the session and every later test fails somewhere
  unrelated. If a control cannot be named, that is a bug in the control.
- **Build dates in local time** (`e2e/dates.ts`). `toISOString().slice(0, 10)`
  is the UTC date, and the server counts calendar days locally — so a suite
  using it passes all day and fails after the UTC date rolls over.

Jest covers pure logic that would be dangerous to get wrong quietly (duration
parsing, token hashing, redaction, slugs). Playwright covers the real flows
against a running stack — it is the only thing that tests the shell, the palette
and the keyboard layer.

Playwright authenticates **once** in a setup project and reuses the storage
state (`e2e/auth.setup.ts`). Do not sign in through the form inside a test unless
the test is about sign-in — the login endpoint is rate limited to five attempts a
minute and a suite that ignores that ends up testing the throttle.

Keyboard shortcuts register in a client effect, so pressing a key straight after
`goto()` races hydration. Use the `ready(page)` helper in `workspace.spec.ts`.

## Known rough edges

- `npm start -w @devos/web` runs `start.mjs`, not `next start`: the config sets
  `output: 'standalone'`, which `next start` does not support. It appeared to
  work, through the wrong entrypoint, while leaking memory — a suite run against
  it slowed down tenfold and tests began timing out.
- `next lint` is deprecated in Next 15 and removed in 16. The web workspace uses
  a legacy `.eslintrc.json` because `eslint-config-next` is not yet a flat
  config. Migrate when moving to Next 16.
- Prisma warns that `package.json#prisma` is deprecated. Moving to
  `prisma.config.ts` means handling `.env` loading manually; it is a Prisma 7
  chore, not a bug.
- The default embedding provider matches **words, not meaning**. The console
  says so on screen rather than implying otherwise. `EMBEDDING_PROVIDER=openai`
  buys real semantic matching and requires a full re-index.
- Export produces JSON, Markdown and CSV, but no ZIP — Node has no archive
  builder in the standard library and one dependency for one download was not
  worth it. Several types in one CSV is not strict CSV; the code says so.
- AWS, GCP and Docker are not integrated. AWS needs request signing (an SDK),
  and Docker needs local socket or command execution, which §26 rules out for
  the MVP. They are listed as unbuilt rather than shown as dead toggles.
- `getWorkersCount()` counts named Redis _connections_, not worker processes.
  It is used only as a yes/no for that reason.
